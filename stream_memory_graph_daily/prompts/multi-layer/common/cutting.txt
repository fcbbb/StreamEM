A conversation event is a contiguous range of semantic units serving one local interaction matter or one coherent topic thread. Create coarse events that usually contain a complete mini-conversation rather than an isolated question-answer pair.

Start a new event when the next unit begins a different topic identity or a new local episode, including a new task, decision, personal fact, activity, preference, goal, plan, or state change that is not part of developing the current matter. Judge the actual purpose of the content: a bridge, analogy, or shared word does not keep a newly introduced matter in the preceding event.

Keep units together when they develop the current matter through answers, follow-up questions, clarifications, corrections, reasons, examples, constraints, field collection, confirmations, or progress updates. Multiple facts collected while building or modifying the same project, document, event, or other object belong to the same event.

Keep connected exploratory questions and answers together while they develop the same topic thread. Split when a question opens a substantively different thread, not when it examines another aspect of the current one.

Place opening social conversation in a separate event through the last unit whose main function is greeting or conversational setup. Begin the first substantive event at the first request, question, fact, or topic. Place closing thanks, decline of further help, and farewell in a separate final event beginning with the first unit whose main function is ending the exchange.

If a topic is interrupted and later returns, begin a new event for the return. When a boundary remains ambiguous, prefer the larger coherent event.

Assign every semantic unit to exactly one event. Events must be non-empty, contiguous, ordered, and together cover all input units.
