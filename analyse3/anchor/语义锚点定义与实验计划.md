# 对话片段语义锚点：定义与实验计划

本目录中的实验脚本使用仓库根目录的相对路径和 `uv` 环境。首次运行先在仓库根目录执行 `uv sync`，然后可使用 `uv run streamem-anchor-build`、`uv run streamem-anchor-pilot` 和 `uv run streamem-anchor-extract`。API 配置默认读取仓库根目录的 `.env`。

## 1. 背景与目标

现有数据由用户与 LLM 的连续对话切割而成，每个片段是一个相对独立的会话。后续希望识别表达相同具体话题或内容的片段，为用户记忆的积累提供基础。

目前的方法是从每个片段中提取 5 个关键词，再依据关键词的平均语义相似度判断片段之间的相关性。该方法可能存在两个问题：

- 关键词之间缺少明确的语义关系，难以完整表达会话的核心话题；
- 泛化词、背景词或偶然出现的词可能引入错误相似性。

本阶段暂定：**每个单主题会话片段只提取一个语义锚点**，并研究这个锚点能否比多个独立关键词更准确、稳定地表示片段的核心话题。

本阶段只讨论语义锚点的定义、提取和评估，不展开建图、社区检测或最终记忆生成方法。

## 2. 语义锚点定义

> 语义锚点是一个能够代表会话主要内容、区分不同话题，并且粒度与可持续积累的用户记忆单元相匹配的稳定主题表达。

语义锚点回答的是：

> 这段会话主要属于哪个具体且可持续积累的话题？

语义锚点不是：

- 对整段会话的完整摘要；
- 若干彼此独立的关键词；
- 一次性的操作步骤或问题细节；
- 已经提取完成的用户记忆。

推荐采用简短主题短语，常见形式为：

```text
具体对象 + 具体方面
```

例如：

```text
客服机器人意图识别模块
Python 项目的依赖管理偏好
日本旅行中的住宿偏好
长距离跑步训练计划
```

“一个锚点”不等于“一个关键词”。一个完整的语义短语可以同时包含对象、方面及其语义关系。

## 3. 三个核心性质

### 3.1 代表性

锚点应当概括会话的主要内容，而不是偶然出现的实体、工具或背景信息。

判定问题：

> 只看到这个锚点，是否能够基本判断该会话主要在讨论什么？

示例：对于“将客服机器人后端从 Flask 迁移到 FastAPI”的讨论：

| 候选 | 判断 |
|---|---|
| Python | 不能充分代表主要内容 |
| FastAPI | 只覆盖一个局部实体 |
| 客服机器人后端框架迁移 | 能代表主要内容 |

### 3.2 区分性

锚点应当能够将当前会话与内容相近但实际话题不同的会话区分开。

判定问题：

> 是否存在许多内容明显不同的会话，也可以毫无违和地使用这个锚点？

如果答案是“是”，说明锚点太宽。例如，“客服机器人项目”可能无法区分意图识别、数据库和服务部署；“客服机器人意图识别模块”具有更好的区分性。

区分性是相对于其他会话而言的，仅观察单个会话无法完整判断。因此，评估区分性时必须加入相似但不同的话题作为困难负例。

### 3.3 记忆粒度适配性

锚点粒度应当适合多段会话围绕它持续积累，并有可能形成一条连贯、有价值的用户记忆。

判定问题：

> 围绕这个锚点聚集多段会话后，是否可能形成一条连贯、有价值的用户记忆？

典型判断：

| 锚点 | 判断 |
|---|---|
| 编程 | 太粗 |
| Python | 太粗 |
| Python 依赖管理偏好 | 合适 |
| 用户这一次询问 `uv add` 的用法 | 太细 |
| 客服机器人项目 | 在项目层面可能合适 |
| 客服机器人意图识别模块 | 当项目内容较多时更合适 |

粒度并非越细越好。太粗会混合多条潜在记忆，太细则难以跨会话积累。

## 4. 单锚点假设

### 4.1 当前假设

对于已经切割好的相对独立、单主题会话，默认提取一个语义锚点。

采用单锚点的预期优势是：

- 强制模型识别最主要的话题；
- 减少泛化词和次要信息造成的错误关联；
- 使锚点更容易理解、检查和解释。

主要风险是：如果唯一锚点提取错误，后续没有其他锚点进行补偿；不同表达也可能造成相同话题之间的遗漏。

本阶段不通过保留多个锚点解决这一风险，而是在提取时生成多个候选，再选择一个最终锚点。容错发生在提取阶段，最终表示仍然是单锚点。

### 4.2 与对话切割的关系

切割与锚点提取可以在同一次 LLM 调用中完成，但逻辑顺序必须是：

1. 先按照对话目标和语义连续性确定切割边界；
2. 再为每个已经确定的片段提取锚点。

需要明确允许多个切割片段拥有相同锚点。不能因为锚点相同而拒绝切割，也不能为了让锚点不同而过度切割。

#### 4.2.1 切割纯度是锚点提取的前置条件

锚点提取假设输入片段已经围绕一个主要话题组织。如果上游切割将两个不
同的话题合并到同一个片段，锚点模型可能会因为无法确定主要话题而输出
`null`，也可能选择错误的话题或生成过于泛化的表达。这类结果不能直接
归因于锚点提取方法本身，应当先检查输入片段的切割边界和话题纯度。

在试验中，`session_0002_seg003` 和 `session_0122_seg003` 都同时包含了
咖啡消费和步数话题。将两个片段分别在步数问题之前切开后，得到的四个
单话题片段均成功生成了锚点，没有再输出 `null`：

| 原片段 | 修正后的内容 | 提取结果 |
|---|---|---|
| `session_0002_seg003` | 咖啡消费 / 步数话题 | `The abstract nature of everyday coffee purchases` / `Today's step count and activity level` |
| `session_0122_seg003` | 咖啡消费 / 步数话题 | `morning coffee purchase` / `today's step count` |

因此，当前实验应将“上游片段是否为纯净单话题”作为锚点评估的前置
检查项。对于不纯净片段，应同时记录切割污染，并在分析中将其与锚点
提取错误分开报告。端到端实验仍可以保留这类片段，但不能仅根据这类
输入的结果判断锚点提取环节的质量。

## 5. 初始提取方法

不直接要求 LLM “总结会话”，而是让它比较不同粒度的候选，再依据三个性质选择一个最终锚点。

建议的初始 Prompt：

```text
你需要从一段用户与 LLM 的会话片段中提取一个语义锚点。

语义锚点不是完整摘要，也不是关键词列表，而是一个简短、稳定的主题表达，
用于表示这段会话主要属于哪个可以持续积累用户记忆的具体话题。

合格的语义锚点必须同时满足：

1. 代表性：能够概括会话的主要内容，而不是偶然出现的信息。
2. 区分性：不能过于宽泛，应能与相近但不同的话题区分。
3. 记忆粒度适配性：粒度适合多段会话围绕它持续积累。

请先考虑一个偏粗、一个合适、一个偏细的候选，然后选择其中最符合上述
三个条件的表达作为最终锚点。

最终锚点要求：

- 默认只输出一个；
- 尽量采用“具体对象 + 具体方面”的简短主题短语；
- 不要输出完整事件摘要；
- 不要使用一次性的操作步骤作为锚点；
- 如果片段没有明确的主要话题，输出 null，不要强行生成。

会话片段：
{{conversation}}

输出：
{
  "coarse_candidate": "...",
  "selected_anchor": "...",
  "fine_candidate": "...",
  "reason": "用一句话说明选择原因"
}
```

开发和分析阶段保留候选与原因；正式运行时可以只保留 `selected_anchor`。

### 5.1 参考段输入

单段输入最有利于保持锚点对目标片段的忠实性，但只观察单段时，LLM 较难判断锚点是否具有区分性、粒度是否过粗。为此，可以在提取目标片段锚点时加入少量参考段。

参考段应当分为两类：

- **可能同话题的近邻段**：帮助识别跨片段保持不变的具体话题；
- **相似但可能不同的对照段**：帮助识别话题边界，避免生成过粗的公共锚点。

只提供预聚类内部的片段存在确认偏差。模型可能因为这些片段被放在一起，就主动寻找过于宽泛的共同点。例如，意图识别、数据库和服务部署都可能被概括为“客服机器人项目”。因此，参考输入不应只有预聚类内部片段，还应包含少量聚类外的困难对照段。

推荐的参考输入形式为：

```text
请只为“目标片段”提取一个语义锚点。

其他片段仅用于帮助判断锚点的区分性和粒度。它们可能与目标片段属于
同一话题，也可能只是表面相似，不能假设预聚类结果一定正确。

请首先依据目标片段判断其主要内容，然后参考其他片段，避免锚点过粗或
过细。不要总结整个片段集合。

目标片段：
{{target_segment}}

可能同话题的近邻段：
{{candidate_neighbors}}

相似但可能不同的对照段：
{{hard_negative_neighbors}}
```

### 5.2 是否提供参考段的已有锚点

核心实验中，默认只提供参考段原文，**不提供参考段已经提取出的锚点**。

已有锚点可能使模型直接复用已有表达、迎合预聚类结果并继承早期提取错误，从而难以判断性能提升究竟来自原始语义上下文，还是来自对已有答案的模仿。

已有锚点只在后续的附加消融实验中提供，并明确限定用途：

```text
已有锚点是自动提取的暂定结果，可能存在错误。
它们只能作为同义表达和命名一致性的参考，不能作为目标片段所属话题的证据。
不得为了采用已有锚点而改变目标片段的主题或粒度。
```

因此，将两个任务区分开：

```text
目标段和参考段原文 → 确定锚点语义
已有锚点列表       → 统一语义等价锚点的表达
```

## 6. 性能评估方法

锚点不存在唯一的标准措辞，因此不使用字符串完全匹配、BLEU 或 ROUGE 作为核心指标。评估直接对应三个定义性质，不将它们线性加权成一个分数。

### 6.1 主指标：合格锚点率

一个锚点只有在代表性、区分性和粒度三项都合格时，才记为合格。

```text
合格锚点率 = 三项都合格的锚点数 / 全部锚点数
```

### 6.2 分项指标

每个样本记录：

- 代表性：合格 / 部分合格 / 不合格；
- 区分性：合格 / 不合格；
- 粒度：太粗 / 合适 / 太细；
- 是否应该输出 null：是 / 否。

结果应分别报告各项比例和错误类型。例如：

```text
代表性合格率
区分性合格率
粒度合适率
三项全部合格率
粒度过粗率
粒度过细率
无主题片段误生成率
```

### 6.3 稳定性辅助指标

稳定性不作为第四个定义性质，而是作为提取方法的可靠性指标。

对同一会话进行轻微扰动或重复提取，判断前后锚点是否表达同一语义：

```text
稳定率 = 扰动前后语义一致的样本数 / 全部扰动样本数
```

可采用的扰动包括删除寒暄、改写措辞、删除非关键句，以及改变模型随机种子。比较的是规范化后的语义是否一致，而不是字符串是否相同。

## 7. 实验计划

### 阶段一：构建小规模评测集

建议首先抽取 150～300 个会话片段，覆盖：

- 主题明确的普通片段；
- 同一项目的不同方面；
- 不同项目中的相同技术或活动；
- 同一领域中的不同偏好；
- 容易产生过粗锚点的片段；
- 只有一次性问题、缺少可持续话题的片段；
- 应当输出 null 的片段。

另外构造一组会话对，用于重点评价区分性：

- 困难正例：具体话题相同，但措辞、实体称呼或讨论角度不同；
- 困难负例：共享项目名、技术名或领域词，但具体话题不同。

会话对只需人工标注“属于同一具体话题”或“不属于同一具体话题”。

### 阶段二：建立对照方法

比较以下三种方案：

| 方案 | 说明 |
|---|---|
| A：现有基线 | 提取 5 个关键词 |
| B：直接单锚点 | LLM 直接输出一个语义锚点 |
| C：候选选择单锚点 | 生成粗、合适、细三个候选后选择一个 |

方案 B 与 C 的最终输出均只有一个锚点。方案 C 用于验证“先比较粒度再选择”是否能减少锚点过粗或过细的问题。

### 阶段三：参考段输入消融实验

在确定单锚点提取方法后，固定相同的模型和提取 Prompt，只改变提供给模型的上下文：

| 方案 | 输入内容 | 目的 |
|---|---|---|
| R1：单段 | 仅目标片段 | 作为无参考上下文基线 |
| R2：随机参考 | 目标片段 + 随机片段 | 判断增加文本本身是否带来变化 |
| R3：预聚类参考 | 目标片段 + 预聚类近邻原文 | 判断近邻是否改善话题识别和命名一致性 |
| R4：近邻与对照 | 目标片段 + 预聚类近邻原文 + 聚类外困难对照原文 | 判断正反参考是否改善区分性和粒度 |
| R5：附加已有锚点 | 在 R4 基础上提供参考段的暂定锚点 | 仅作为附加实验，判断命名一致性收益及锚定偏差 |

所有方案都只为目标片段输出一个锚点，不为整个参考集合生成公共锚点。R3～R5 中的预聚类关系均被视为可能有误的候选关系，而不是正确标签。

为了公平比较：

- 每个目标片段使用相同数量的参考段；
- 控制总输入长度，避免结果只是由上下文长度差异造成；
- 同一目标片段在各方案中保持不变；
- 参考段顺序可以交换一次，用于检查顺序敏感性；
- R5 单独报告，不与“不提供已有锚点”的核心方案混合统计。

该实验重点检验：

- 预聚类参考是否提高区分性，还是使锚点普遍变粗；
- 加入聚类外困难对照后，过粗锚点是否减少；
- 提供已有锚点是否只改善措辞一致性，还是会降低代表性；
- 当预聚类中混入错误片段时，目标锚点是否被带偏。

### 阶段四：人工质量评估

将三种方案的结果匿名并打乱顺序，由标注者根据统一标准判断：

1. 是否代表主要内容；
2. 是否能与给定困难负例区分；
3. 粒度是太粗、合适还是太细。

建议至少一部分样本由两名标注者独立判断，以检查三个性质的定义是否足够清晰。如果分歧较多，应优先修订标注说明和示例，而不是立即修改模型。

### 阶段五：相似性分离实验

分别使用三种表示计算已标注会话对的语义相似度，观察：

- 困难正例的相似度分布；
- 困难负例的相似度分布；
- 两类分布的重叠程度；
- 在相同高精度要求下，各方案能够保留多少正确正例。

不同方案应分别扫描相似度阈值，不能使用同一个固定阈值直接比较。此处不对多个指标进行线性加权。

由于错误连接通常比暂时漏掉连接更容易污染用户记忆，实验结果应优先观察高精度区域；同时保留召回率，用于判断单锚点是否造成了不可接受的遗漏。

### 阶段六：稳定性实验

从评测集中选取一部分片段，进行轻微改写、删除寒暄和重复采样，比较三种方法的输出稳定性。

重点观察：

- 单锚点是否因为措辞变化而频繁改变；
- 候选选择是否比直接生成更加稳定；
- 5 个关键词是否会因为某个关键词变化而显著改变整体表示。

## 8. 实验结论需要回答的问题

实验最终不只回答“哪个指标最高”，而应回答以下问题：

1. 单个语义锚点是否比 5 个关键词具有更高的三项合格率？
2. 单锚点是否明显减少了困难负例之间的错误相似性？
3. 单锚点造成的困难正例遗漏是否可以接受？
4. “候选生成后选择”是否优于直接生成一个锚点？
5. 单锚点在轻微文本扰动下是否保持稳定？
6. 主要错误来自代表性不足、区分性不足，还是粒度过粗或过细？
7. 输入预聚类参考段是否优于单段输入？
8. 同时加入聚类外困难对照，能否减少预聚类上下文导致的过粗锚点？
9. 提供参考段的已有锚点，是改善命名一致性，还是引入了明显的锚定偏差？

## 9. 当前决策与暂不处理事项

当前暂定：

- 每个单主题片段使用一个最终语义锚点；
- 锚点采用完整的语义短语，而不是单个词；
- 锚点只使用三个核心性质定义：代表性、区分性、记忆粒度适配性；
- 通过生成多个候选并选择一个结果提供提取阶段的容错；
- 将“单段输入”和“参考段输入”作为需要通过消融实验比较的方案；
