# 图构建与社区检测实验结论

## 1. 实验范围

当前实验使用 277 个 segment anchor，社区检测采用 Leiden，输入为：

`F:\StreamEM\analyse3\anchor\artifacts\anchor_dataset_v1\output\new_outputv2_full_manual.jsonl`

Pairwise 指标基于 1505 个非 uncertain 标注对计算，其中 224 个为 same_specific_topic，1281 个为非同主题。结果只反映当前数据、anchor 表示、候选标注对和阈值设置下的表现，不代表对所有数据的绝对最优。

## 2. 当前推荐方案

对于流式场景，推荐：

```text
在线建边：kNN k=10 + similarity threshold 0.5
社区检测：Leiden
社区更新：按批次或受影响区域周期性刷新
答案生成：查询级跨社区证据检索与聚合
```

推荐理由：

- 新节点到达后即可检索已有节点并建边，不需要等待 mutual-kNN 确认；
- 相比 k=5，Recall 和 F1 略高；
- 孤立节点比例更低于未加阈值的稠密 kNN 方案；
- Leiden 在当前实验中整体略优于 Louvain；
- kNN k=10 + 阈值 0.5 与 mutual-kNN k=10 + 阈值 0.5 得到相同的社区划分，但前者更适合在线维护。

## 3. 主要结果

| 建边规则 + 算法 | Community Precision | Recall | F1 | 边数 | 社区数 | 孤立节点比例 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| mutual-kNN k=5 + 阈值 0.5 + Leiden | 0.679 | 0.652 | **0.665** | 281 | 107 | 22.7% |
| kNN k=10 + 阈值 0.5 + Leiden | 0.612 | **0.710** | 0.657 | 461 | 98 | 21.3% |
| kNN k=5 + 阈值 0.5 + Leiden | 0.595 | 0.696 | 0.642 | 345 | 99 | 21.3% |

kNN k=5 与 k=10 的差异不大。k=10 多建立一些边，使召回略有提升，但社区数量和孤立节点比例基本不变。因此 k=5 可以作为更稀疏、成本更低的备选，k=10 作为流式主方案更稳妥。

## 4. 社区结构解读

以 mutual-kNN k=5 + 阈值 0.5 + Leiden 为例：

- 277 个节点形成 107 个社区；
- 63 个社区是单节点社区，占社区数 58.9%；
- 214 个节点属于非单节点社区，占节点数 77.3%；
- 最大社区包含 18 个节点，没有出现过大的混杂社区；
- 图平均度为 2.03，整体较稀疏；
- 281 条边中有 272 条位于最终社区内部，占 96.8%；
- 基于标注对的社区内部纯净度为 0.679；
- 图的 modularity 为 0.916，说明社区与当前图结构高度一致。

这些结果表明，当前图能够形成较清晰的细粒度语义社区，但社区较碎，不能直接把一个社区当作一个问题的完整证据集合。

## 5. 对 broad 问题的处理结论

Movie、Books、Music 等问题的不同证据，可能分别落在“战争电影”“演员表现”“文学主题”“音乐风格”等细粒度社区中。它们内容上未必有足够高的 anchor 相似度，因此不应强制要求属于同一个全局社区。

后续答案生成应采用两层结构：

```text
全局语义图：发现可复用的细粒度主题社区
查询级证据集合：根据当前问题跨多个社区召回、筛选和聚合证据
```

因此，全局社区质量应继续用纯净度、召回率和结构指标评估；问题回答质量则另外评估 evidence recall、evidence precision 和 evidence bundle completeness。

## 6. 最终判断

当前结果足以支持：

- 语义图的初版构建；
- 细粒度主题发现；
- 查询时的候选证据召回和图邻居扩展。

当前结果不足以支持：

- 仅依靠单个固定社区完成 broad 问题的全部证据聚合；
- 将 Community F1=0.665 直接解释为最终答案准确率；
- 证明当前规则对所有流式数据都绝对最优。

在当前流式约束下，正式采用 `kNN k=10 + 阈值 0.5 + Leiden` 作为主方案；保留 `mutual-kNN k=5 + 阈值 0.5 + Leiden` 作为离线纯净度较高的对照方案。
