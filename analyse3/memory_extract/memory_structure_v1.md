# 主题记忆结构 v1

## 定义

一个纯化后的社区（或 group）对应一个主题记忆对象。主题记忆记录用户与系统围绕某个主题已经讨论过的内容，并允许后续相关社区继续补充和更新。

第一版只做主题级结构化，不推断用户的偏好、立场、兴趣、知识水平或其他个人属性。

摘要和要点应描述对话中实际出现的内容，优先使用“对话讨论了……”这类表述；除非用户明确表达，否则不要使用“用户认为……”“用户关注……”等归因性表述。

## 内容保留准则

主题记忆中的保留内容分为 `topic_context` 和 `user_memories`，二者不等同。主题记忆、用户记忆和瞬时对话内容需要区分。

### 用户记忆

描述用户或用户持续状态的信息，例如用户明确表达的事实、偏好、目标、决定、计划或约束。用户明确表达的事实、决定和目标可以作为用户记忆保留。

### 主题上下文

为了后续继续讨论某个主题而保留的内容，例如主题已经讨论过的方面、形成的结论、未解决的问题、设计约束和下一步方向。主题上下文可以包含 AI 的回答，但不等同于用户记忆。

### 瞬时对话内容

只对当前轮次有效的普通问答、泛泛知识解释、重复内容、寒暄和没有后续作用的回答。此类内容通常不进入主题记忆。

判断是否保留时，检查内容是否改变了主题的后续讨论状态。主题状态包括：当前讨论对象、已经明确的内容、未解决的问题、已确定的方向或约束，以及下一步可能继续的内容。

### 用户问题的保留条件

用户问题本身通常不是用户记忆。满足以下任一条件时，可以作为主题上下文保留：

1. 提出了具体的未解决问题；
2. 改变了主题的范围或讨论方向；
3. 表达了任务约束、判断标准或选择条件；
4. 指向明确的下一步行动。

普通的一次性问题，如果没有形成开放问题、约束或后续方向，通常只保留在原始对话中。

### AI 回答的保留条件

AI 回答不能仅因为已经生成就进入记忆。满足以下任一条件时，可以作为主题上下文保留：

1. 用户明确接受、确认或继续使用该回答；
2. 后续对话引用了该回答，或以它为基础继续展开；
3. 回答包含当前项目或主题专属的结论、规则或判断；
4. 回答解决了一个需要持续追踪的主题问题。

泛泛的知识解释、没有被后续使用的回答和重复回答通常不进入主题记忆。

### 简化判断表

| 内容 | 保留方式 |
|---|---|
| 用户明确的事实、决定、目标 | 作为用户记忆保留 |
| 用户提出的具体未解决问题 | 作为主题中的开放问题保留 |
| 用户提出的普通一次性问题 | 通常只保留在原始对话 |
| 用户提出的设计约束或下一步 | 作为主题状态保留 |
| AI 的泛泛知识解释 | 通常不保留 |
| AI 的项目专属结论 | 作为主题上下文保留 |
| 被用户接受或被后续引用的 AI 回答 | 作为主题上下文保留 |

最简规则是：用户问题只有在形成开放问题、约束或下一步时保留；AI 回答只有在形成被采用、被引用或对当前主题有持续作用的上下文时保留。

## 最小结构

```json
{
  "memory_id": "mem_001",
  "topic": "人工意识与主观体验",
  "summary": "对话讨论了人工智能是否可能产生意识、主观体验的本质，以及人工意识可能带来的哲学和伦理问题。",
  "topic_context": [
    {
      "type": "open_question",
      "content": "人工智能是否可能具有意识"
    },
    {
      "type": "topic_conclusion",
      "content": "讨论了主观体验和意识的关系"
    },
    {
      "type": "scope",
      "content": "讨论了人工意识可能带来的哲学和伦理问题"
    }
  ],
  "user_memories": [],
  "source_anchors": [
    "Philosophical implications of conscious AI",
    "The hard problem of consciousness and subjective experience"
  ],
  "source_segments": [
    "session_0002_seg002",
    "session_0029_seg002"
  ]
}
```

## 字段说明

- `memory_id`：主题记忆对象的稳定标识。
- `topic`：纯化 group 的统一主题。它不一定等于单个 anchor；多个 anchor 时，应提炼它们的共同父主题。
- `summary`：该主题当前内容的简要概括。
- `topic_context`：为后续主题讨论保留的开放问题、主题结论、约束、方向或其他持续上下文。
- `user_memories`：用户明确表达的事实、偏好、目标、决定、计划或约束。
- `type`：由模型根据具体内容生成的开放类型标签。第一版只要求标签准确、简洁、非空，不预设封闭枚举。
- `source_anchors`：用于形成主题的原始 anchor，保留作可追溯证据。
- `source_segments`：支持该记忆的原始 segment。

提取实验阶段使用 `case_id`（`community_id::group_id`）标识一次输入样本；稳定的 `memory_id` 应在后续融合阶段创建或匹配，不由提取 prompt 自行生成。

## 提取约束

1. 一个纯化 group 输出一个主题记忆对象。
2. `topic` 可以基于多个 anchor 归纳，但必须保持在原始对话语义范围内。
3. `summary`、`topic_context` 和 `user_memories` 只保留对话中明确出现或直接可概括的内容。
4. 不把 AI 的回答自动当作用户观点。
5. 不从单次讨论推断用户的长期兴趣、偏好、立场或能力。
6. 所有内容都必须能够通过 `source_anchors` 或 `source_segments` 回溯。

## 后续融合

当新的纯化 group 到来时：

1. 判断新 group 是否属于已有 `topic`。
2. 如果属于同一主题，补充或修正 `summary`、`topic_context` 和 `user_memories`。
3. 合并新的 `source_anchors` 和 `source_segments`，并去重。
4. 如果无法确定是否属于同一主题，第一版暂不强行合并。
5. 如果是新主题，则创建新的 `memory_id`。

第一版融合只处理重复、补充和修正，不建立复杂的冲突图或用户属性模型。
